# OpenGuardian 研究报告
## AI 驱动的个人数字安全防护平台

**项目版本**：v0.7.0  
**团队**：温州科技职业学院 数智技术学院 计网24-3  
**日期**：2026年8月

---

## 摘要

OpenGuardian 是一个面向个人用户的 AI 驱动数字安全防护平台，采用多智能体（Multi-Agent）架构，融合实时威胁情报、深度检测引擎与大语言模型（LLM）交互能力，实现"检测 → 验证 → 处置 → 教育"的安全闭环。本报告从技术架构、核心算法、实验数据三个维度阐述项目的创新性与工程完成度。

---

## 一、研究背景与问题

### 1.1 个人安全困境

- 个人终端缺乏企业级安全防护（EDR/XDR 多面向企业）
- 免费杀毒软件存在误报率高、告警无解释、用户看不懂的问题
- AI 时代钓鱼、勒索、深度伪造（Deepfake）攻击手段升级
- 传统安全工具"只报警、不解释"，用户无法理解风险本质

### 1.2 现有方案不足

| 方案 | 局限 |
|---|---|
| Windows Defender | 仅基础防护，无 AI 解释，告警不可操作 |
| 商业杀毒软件 | 误报率高，弹窗轰炸，无教育价值 |
| 通用 AI 助手 | 无系统检测能力，回答泛化，不基于真实数据 |

### 1.3 OpenGuardian 的解法

**核心命题**：让安全检测"可解释、可操作、可教育"——用 AI 把专业安全知识翻译成用户能懂、能行动的建议。

## 二、技术架构

### 2.1 总体架构

```
┌─────────────────────────────────────────────────┐
│                  前端 (PyWebView + HTML/JS)        │
│        监控仪表盘 · 智能助手 · 配置向导           │
└──────────────────────┬──────────────────────────┘
                       │ SSE 流式 / REST / WebSocket
┌──────────────────────▼──────────────────────────┐
│              FastAPI 服务层 (端口 8300)           │
│  意图路由 · 流式响应 · 中间件(限流/追踪)          │
└──────────────────────┬──────────────────────────┘
                       │ Agent 总线
┌──────────────────────▼──────────────────────────┐
│              多智能体协作层                       │
│  Consultant → Detector → Verifier → Reflector    │
│        → Triage → Educator → Executor            │
└──────────────────────┬──────────────────────────┘
                       │
┌──────────────────────▼──────────────────────────┐
│   知识层: SQLite · 威胁情报 · 恶意特征 · 术语库   │
│   LLM层: 25家提供商 · 连接池 · 重试 · 降级        │
└─────────────────────────────────────────────────┘
```

### 2.2 多智能体流水线

检测流程采用**七段式流水线**（Pipeline），每段专职：

| 阶段 | 智能体 | 职责 | 技术 |
|---|---|---|---|
| 1 | Detector | 并行扫描 7 类安全项 | ThreadPoolExecutor(8) |
| 2 | Asset | 密码强度+账户策略审计 | zxcvbn + net accounts |
| 3 | Verifier | 对抗性验证（区分真实威胁/误报） | 确定性规则+LLM 复核 |
| 4 | Reflector | 反思覆盖盲区+历史对比 | 边界信号分析 |
| 5 | Triage | 分级处置（自动/建议/仅报告） | 风险分级引擎 |
| 6 | Educator | 安全科普（案例库+RAG） | 29 案例+114 术语 |
| 7 | Executor | 一键处置（白名单保护） | 进程管理 |

### 2.3 关键设计：对抗性验证（Verifier）

传统扫描器**只报警**，误报率高。OpenGuardian 引入**对抗性验证**：

1. **确定性快速通道**（毫秒级）：白名单、系统目录、阈值边界检查
2. **LLM 深度通道**：模糊案例调用模型做语义判断
3. **三态输出**：CONFIRMED（确认）/ REFUTED（证伪）/ UNCERTAIN（待定）

实测效果：6 项风险 → 6 confirmed（全部确定性确认，误报 0）。

### 2.4 关键设计：LLM 可靠性工程

| 问题 | 方案 |
|---|---|
| API 波动 | 连接池复用 + 3 次指数退避（1s/2s/4s） |
| 流式中断 | 自动降级：流式 → 非流式 → 兜底文案 |
| 超时 | 确定性类型跳过 LLM，硬超时保护 |
| 多提供商 | 25 家统一 OpenAI/Anthropic 双格式适配 |

## 五、创新点总结

1. **多智能体安全流水线**：检测→验证→反思→分级→处置，企业级 EDR 思路落地个人端
2. **对抗性验证机制**：不是"报了就算"，而是主动证伪，显著降低误报
3. **AI 可解释安全**：LLM 把检测结果翻译成白话+可操作建议，解决"看不懂告警"痛点
4. **本地优先+云端增强**：威胁情报本地化，检测不依赖网络；LLM 可选 25 家或本地 Ollama
5. **零信任数据源**：威胁情报全部来自权威源（ESET/URLhaus/FireHOL），非模拟数据
